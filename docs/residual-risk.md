# Residual risk

Fairlead is a deterministic Cedar PEP on hooked agent tool calls. It is not unhackable. Prompt injection is not solved.

## Split

Fairlead defends the agent.
The org defends Fairlead.
Receipts prove what the PEP saw, not that every tool call hit the PEP.
Local admin uninstall + disabled fleet telemetry is detect-not-prevent.
Pin+doctor does not stop `rm` hooks after arm.

No kernel claim. A host hook is a policy gate, not an isolation boundary: an agent or child process running as the same user is not contained by it, and a Claude Code hook that never loads is not covered by `onFailure`. Fairlead provides no OS sandbox (Seatbelt, bubblewrap, seccomp stay the host's job; F-BYP-09). `doctor` and `arm` read the host's config and report it. Claude: every readable scope (managed file and `managed-settings.d`, `FAIRLEAD_CLAUDE_SETTINGS`, project local and shared, user), resolved like the host (managed outranks the rest; among managed files a later one replaces an earlier single value; MDM and remote settings outrank the files and are not read), must carry a Fairlead PreToolUse and PermissionRequest hook with matcher `*` and `onFailure: block`, no effective `disableAllHooks`, `sandbox.enabled` true, `allowUnsandboxedCommands` false and `failIfUnavailable` true, and `claude --version` must be 2.1.295 or newer (an older host ignores `onFailure`; probed on 2.1.285: the hook still runs, failures still pass). Claude is checked only when some scope carries a Fairlead Claude hook. Cursor `sandbox.json` `type` not `insecure_none` (`~/.cursor` and the current directory). A gap warns on a plain seat and refuses on a managed seat. It cannot see Cursor's Run Everything mode, team-admin policy or other settings scopes, so a passing check is not proof the sandbox is on. Anti-bypass is pin + detect, not prevent-admin (NFR-08, F-BYP-10).

Claude Code has no `failClosed`, but 2.1.295 and newer take `onFailure: "block"` on command and HTTP hooks: a missing binary, crash, timeout, exit other than 0 or 2, or invalid JSON then blocks the call (Claude Code hooks docs; not yet run live on 2.1.295 here). `install-hooks` and the managed sample write it; `doctor` and `arm` require it, and warn on a plain seat or refuse on a managed seat when the host is older than 2.1.295. Still open on every version: a hook entry that never loads (managed `disableAllHooks`, a scope the host does not read, MDM or server-managed settings Fairlead cannot see), `SubagentStart` (cannot block) and `SubagentStop`. The opt-in `managed/claude-managed-strict.json` (permission mode `dontAsk` plus an allowlist, managed-only rules) and the OS sandbox are the layers that hold without a hook. Fairlead's process still emits deny JSON + exit 2.

MCP `PreToolUse` deny may be ignored ([anthropics/claude-code#33106](https://github.com/anthropics/claude-code/issues/33106)). Shell and file gates still run. Do not put an LLM on the MCP deny path.

`--dangerously-skip-permissions` (YOLO): official docs say PreToolUse deny still applies. GitHub [#20946](https://github.com/anthropics/claude-code/issues/20946) (async race) and [#53589](https://github.com/anthropics/claude-code/issues/53589) (no-fire) disagree. Observed on Claude Code 2.1.285 (2026-10-08, local mock API, real `fairlead` binary): `PreToolUse` fires under `--dangerously-skip-permissions` and exit 2 blocks the tool. That is one version and the main session only; the async-race and subagent reports above are not retested. Not Dual LLM. Not a proxy.

## In scope

Cursor hook stdin → one Cedar pack (`baseline.cedar`). Default deny, forbid-wins. Crash / invalid JSON / Cedar error in **this** process → deny JSON + exit 2. `doctor` refuses to arm if fixtures miss, `failClosed` is not JSON `true` on shell/MCP/read, or last-armed hashes drifted. `arm` re-runs those fixtures on the pack bytes it is about to pin (including first arm with no pin). `--i-reviewed-pack` accepts pack-hash drift only; it never skips fixtures. OSS pack drift refuses auto-arm until that flag. Live hooks read cedar off disk, but an armed seat checks those same bytes against the pin (and the binary, and the file `FAIRLEAD_HOOKS` names) before every evaluate, and against `org.pub` when one is managed. On an OSS seat (no `org.pub`) the pin is an unsigned file in the pack directory, so a same-UID rewrite of pack and pin together still matches its own pin; that ceiling stays. On a managed seat (an `org.pub`, an `armed.stamp`, or a pin in the managed directory; no org key is needed) the pin lives only in the managed directory and the pack copy is never read: a pin or directory that is not root-owned and group/other-write-free denies (`fairlead deny: pin writable`), and a pin missing while `armed.stamp` exists denies (`fairlead deny: pin missing`).

`net.egress` never-granted is the **pack** (`baseline.cedar` F-DEF-03), not an engine guarantee. A different pack can grant it.

Session taint is per host `conversation_id` on disk (`session_path` hashes the id). New chat = cold slate. Fairlead restart keeps JSONL flags.

## Out of model

- A local admin who uninstalls Fairlead, deletes hooks, or disables fleet telemetry. A command typed in the IDE Terminal is not an agent Shell tool and never reaches the PEP, same class as deleting hooks after arm.
- Tool calls that never reached the PEP (YOLO subagents and other Claude versions, Cloud user-hooks gap, Cursor Write if `preToolUse` matcher `Write` is stripped). Cursor `beforeReadFile` is handed file contents, so a path the host never opens does not reach that hook. `preToolUse` matcher `Read` is the path check. If a missing path still returns file-not-found after that matcher is installed, the host did not send `preToolUse`.
- Cursor host `failClosed` blocking the IDE (CI cannot spawn Cursor; suite 8 tests our process + a `/bin/false` fixture)
- Claude host timeout / missing binary / invalid JSON: closed by `onFailure: block` on 2.1.295+, open on older (our process must still deny)
- Org-signed policy packs (not in this release, F-BYP-04)
- Rug-pull tool-descriptor hash (suite 9, P1)
- Quarantine beyond one pipe. Suite 10 holds for `get_latest_issue` behind `fairlead mcp-proxy`: the raw body is absent from the proxy's `tools/call` result on stdout (CI uses stub extractors; the live NuExtract/llama.cpp path is not run in CI). Only that result is rewritten. Upstream notifications on stdout and upstream stderr pass through as is, so a hostile server can still print raw text there; whether Cursor puts either into the model window is unverified. The title is a short line over letters, digits, space and `_ . , # ( ) ' - – —`. That limits syntax, not meaning: `curl 127.0.0.1` is a legal title and the model may act on it (the Gate denies the literal command via F-DEF-03 and `F-Q-ARG`). A live handle record faces `F-Q-ARG` on Shell, Fetch, McpCall, and FileWrite even when the call contains neither string (all four host adapters; `suite10_value_forbid_fires_on_every_host_adapter` and `suite10_boring_shell_carrying_title_is_denied`). One `handles.jsonl` covers every conversation in that session dir, so `ls` and `pytest -q` deny with it. Same family as F-Q-09. Web, Slack, email pipes, paste, `cat`/shell output and repo files are not quarantined (F-Q-09). Not CaMeL's interpreter, no provable-security claim.
- Weekly partner attack-suite report (F-AUD-05, P1)
- Fleet coverage: the kill switch and the osquery pin ship as files (see Goal 11 below); there is no heartbeat daemon, no dashboard, no MDM. Receipts are hook surface, not host coverage. An empty receipt log is not a finding; the pin query is.
- Write/Read TOCTOU after allow: Fairlead `canonicalize` / `read_link` at hook time (depth 40). Cursor opens the file later. A Cedar bool does not close that race (`notes.md` regular at T0, swapped to a symlink onto `.env` at T1).
- Shell inspect vs exec TOCTOU (5b): `python`/`node` script, `-c`, `-e`, argv0 `pytest`, and `python -m pytest`/`unittest`/`doctest` are F-DEF-09. The race that remains is `npm`, `npx`, `cargo`, and `go`: those still run repository code. `tsc` stays boring and does not run the program. Doctor still prints the TOCTOU line. Do not build a wrapper, a seatbelt profile, or seccomp.
- Hook bypass (subprocess, native HTTP, MCP off-side): kernel-wrap (Leash/InnerWarden).

## Receipts

Ed25519 receipts name `binary_sha256`, `policy_pack_sha256`, and `hooks_sha256` for a decision that happened. They are not coverage. A seat with zero receipts is a fleet finding, not a Cedar miss. MVP has no tools-without-receipts / heartbeat tamper indicator.

### Goal 11: what the fleet signal is, and what it is not

The only fleet finding Fairlead ships is a pin check: `managed/fleet-pin-policy.sql`, run by the customer's osquery / Fleet / Kolide. It fails only while a `Cursor`, `cursor-agent`, or `claude` process is running and the managed hooks file or the binary no longer hashes to the armed value. An empty or old `receipts.jsonl` is not a finding: it looks the same whether the IDE is closed, idle, asleep, or unhooked, and alerting on it pages every parked laptop. `fairlead stats` printing `coverage gap` is a zero denominator, not an alert. If the customer never loads the query, the hole is silent and Fairlead still works.

Harnesses where a tool call can run with no hook process and so no receipt. The hook cannot see these, and Fairlead does not try to detect them in Rust:

- Claude headless `claude -p`: reported as running tools with no `PreToolUse` across permission flags ([#33343](https://github.com/anthropics/claude-code/issues/33343), through 2.1.142). Not reproduced on 2.1.285: with a project `.claude/settings.json` the real `fairlead` ran as `PreToolUse` under `claude -p`, allowed `ls` and blocked `echo` and `curl` (default-deny) in both `acceptEdits` and `--dangerously-skip-permissions`. Other versions, `--bare`, and managed-only settings are untested.
- Claude YOLO / `bypassPermissions`: docs say deny still applies; [#20946](https://github.com/anthropics/claude-code/issues/20946) (hook fires but the command already ran) and [#53589](https://github.com/anthropics/claude-code/issues/53589) (no fire) disagree. Claude subagents with `bypassPermissions` are reported to skip the hook too ([#43772](https://github.com/anthropics/claude-code/issues/43772)). Three verified receipts do not prove every path.
- Cursor Cloud Agents: `~/.cursor/hooks.json` is not loaded; hooks do not run during the early read-only turns; dedicated `beforeMCPExecution` / `afterMCPExecution` are deferred. Project `.cursor/hooks.json` and enterprise-managed Shell / file hooks run once the VM is writable.
- Claude 2.1.285 and older: timeout, crash (exit 127 included), and invalid JSON proceed; `onFailure: block` (2.1.295+) turns those into a block. `allowManagedHooksOnly` chooses which settings files may load hooks; it does not hash the hook binary.
- Cursor: `hooks.json` is not loaded in a window with no workspace; a nested monorepo `.cursor/hooks.json` has no documented load path; a missing managed file is fail-open because lower sources still run.
- Cursor's enterprise audit log does not record a Shell call the hook missed. `cursor.hook.execution_complete` exists only when a hook ran.

Do not read `state.vscdb`, shell history, or Claude session JSONL to infer that a tool ran. They hold prompts, and none of them is a stable audit contract.

### Goal 11: live-check status (2026-10-08)

Cursor hooks docs as read on this date; Claude Code 2.1.285; osquery 5.23.1 on macOS. Each line says how it was established.

- Claude exec form (`command` + `args`) and settings `env` reaching the hook: **proven live** on 2.1.285 with a project `.claude/settings.json` under `claude -p`. A `UserPromptSubmit` hook spawned the real `fairlead` binary with `args ["hook","claude","pretool"]`; the settings `env` `FAIRLEAD_ROOT` overrode a conflicting shell export; the signed receipt landed in the temp `FAIRLEAD_RECEIPTS` and its `policy_pack_sha256` equalled the temp pack, not the repo pack. Negative control: the same entry without `args` ran the binary with no subcommand and wrote no receipt (fail-open). Needs 2.1.139 or newer; the Homebrew cask here was 2.1.22 and would have silently ignored `args`. Probe 2026-11-03 on 2.1.285: a hook entry with an unknown `onFailure` key still ran and `claude doctor` raised no settings error, so the key is ignored there (no new fail-open, but no protection either).
- Claude `PreToolUse` through the real binary, `claude -p` tool calls, YOLO: **observed** on 2.1.285 against a local mock Anthropic server (`ANTHROPIC_BASE_URL`, scripted `tool_use`, no credit). Real `fairlead hook claude pretool` with a temp pack: `ls` allowed, `echo hi` and `curl` denied, same in `acceptEdits` and `--dangerously-skip-permissions`; the tool result carried `PreToolUse:Bash hook error: fairlead deny`. A scripted `Agent` tool call also passed the hook (tool name on the wire is `Agent`). Mock-only: no real model, one version, unarmed pack (receipts for these runs were not checked; receipt signing is covered by `cargo test`). With a stand-in hook: exit 0/2 as expected, timeout and missing binary fail open (2.1.285, before `onFailure` existed), `PermissionRequest` fired on `curl`. Not run: `PermissionRequest` through the real binary, subagents spawned with `bypassPermissions`, `--bare`.
- Claude `allowManagedHooksOnly` and the managed path: **docs only**, deliberately untested. It needs admin and would switch off the seat user's own hooks.
- Cursor managed hooks: **observed live** (2026-10-08, Cursor 3.6.21, macOS 15.7.3, Pro plan, `managed/live-probe-cursor.sh` Phase A and B; raw evidence is not published). The managed file at `/Library/Application Support/Cursor/hooks.json` was loaded on a Pro seat; it and the user file both ran, and a managed deny beat a user allow; `command` ran through a shell (env prefix applied, quoted path with a space ran); a rewritten managed file took effect without a Cursor restart (restart absence is the operator's statement); the real wrapper at the managed path denied a curl while `ls` still ran, and the signed receipt's `hooks_sha256` equalled sha256 of the managed file. The same probe showed Cursor sends `"cwd":""` for `beforeShellExecution` (with `workspace_roots` filled); the hook now falls back to `workspace_roots[0]` so relative scripts are inspected in the workspace and not in the hook process's own directory. One machine, one version, one plan. Full matrix (later run, same machine, raw evidence not published): user deny with managed allow also denies. Receipts exist for Shell, Read, Write/Delete (action `FileWrite`), SubagentStart and MCP. The staged file had no Grep matcher, so that Grep ran with no receipt; Cursor's matcher list includes Grep, and the template now subscribes and evaluates it as FileRead. Glob is not in that list (the Claude map marks it unsupported), so a Glob still runs with no receipt. `failClosed: true` blocked on a missing binary, exit 1, a 15 s sleep and non-JSON output (the cause of the timeout case is not established; Cursor showed exit code 1). Drift: after the pack changed the hook did not refuse and signed an allow with the new hash. The query that was run on those digests (dispo copy of `fleet-pin-policy.sql`, three EXISTS rows: hooks, binary, wrapper) still returned 1 row with a `baseline.cedar` hash row set to the receipt's `policy_pack_sha256` `99acbd11…`, because that SQL never reads the row. The same query with the binary row set to the one-byte digest `524d8a46…` returned 0. The workspace query now also requires `sha256` of `baseline.cedar` and of the schema file. That is the file digest osquery stores, not `policy_pack_sha256` (`sha256` of a domain prefix plus the two file digests). A sqlite row whose `sha256` is `99acbd11…` is not a hash osquery would emit for the cedar file. The toy case "baseline.cedar edited" was not a re-hash of the T5 bytes; those files were already restored. That probe predates the live check. Since then an armed seat (a parseable `last-armed.json`) checks before every Cedar evaluate: the schema and cedar bytes it is about to parse must hash to the pinned pack (`fairlead deny: policy drift`, also for an unparseable pin), the running binary to the pinned binary (`fairlead deny: binary drift`), and the file named by `FAIRLEAD_HOOKS` to the pinned hooks digest (`fairlead deny: hooks drift`; `install-hooks` writes that variable into every command, and an armed seat with it unset denies). The receipt's `policy_pack_sha256` is the digest of the same buffers that were parsed. A legitimate pack or binary update denies every call until `arm` runs again. With a managed `org.pub`, the pack digest must also carry that key's signature in `pack.json` (`fairlead deny: pack signature`). Ceilings. A seat with no managed directory (plain OSS): `last-armed.json` is unsigned in a user-writable directory, so a same-UID process that rewrites the pack and the pin together still matches its own pin, and a deleted pin evaluates as unarmed. A managed seat closes both for a non-admin agent, with or without `org.pub`: the pin and `armed.stamp` live in the root-owned managed directory (an existing managed directory is the opt-in; `arm` run as root writes the stamp, then the pin, and never a pack pin), the hook reads only that pin, denies when the pin or directory is writable by anyone but root, and denies when the stamp exists and the pin does not; the hook never writes either. A self-managed seat (no `org.pub`) gets no signed roll: an update is a root `arm --i-reviewed-pack`. With `org.pub`, an update needs no re-arm window: an org-signed `pack.json` that names the new pack digest, the new binary digest and generation exactly pin+1 is accepted in place of the pinned pack and binary, while the old pin keeps working until `arm` installs the new one. What stays residual on every tier: a local admin can replace any of it (F-BYP-10, detect not prevent); a replaced binary that drops the check cannot police itself, and a non-admin cannot be stopped from writing a user-owned binary or hooks file path (on a managed seat `doctor` and `arm` refuse while the managed dir, the binary or the `FAIRLEAD_HOOKS` file, or its parent, is not root-owned and free of group/other write bits; the check reads mode bits only, not ACLs, and a local admin passes it; the osquery hash row is the detector, not this code); and anything that never reaches a hook (IDE terminal, children of an allowed npm/cargo, a deleted hooks file) is untouched. A user-owned hooks `command` still points away from the checker, so the root-owned Cursor managed hooks file and binary are part of the same opt-in; the refusal above enforces the paths Fairlead knows (the binary and `FAIRLEAD_HOOKS`), not which hooks file Cursor loads. Rejected on purpose: a codesign or Team ID self-check does not choose the path Cursor execs, and an ad-hoc signature satisfies its own requirement; an Endpoint Security or eBPF observer cannot be loaded by the seat user, must not live in the hook binary, and stays the F-BYP-09 partner path. The osquery file hash of the cedar and the schema remains the detector outside the hook process, not the receipt field `policy_pack_sha256`. The kill switch state machine ran live (deny, stamp survives deleted `kill.json`, signed clear lifts). Fixes from that run: `verify-receipt` now reads JSONL, kill receipts carry the real action label. `afterShellExecution`, `afterMCPExecution`, and `subagentStop` do not sign receipts (observe path), so a missing row is not evidence the event was skipped. Not tested: Teams/Enterprise, other versions or OSes, other Auto-run modes (Ask, sandbox, Run everything), `cursor-agent` (not logged in), the Hooks output panel.
- Pin predicate: **proven** on real osquery 5.23.1 (`check-install.sh`) and under a real 2 s snapshot scheduler (`check-idle-proxy.py`: edit, delete, binary swap and restore flip the result within one tick; the no-IDE variant never fails). Zero-row results do log as empty snapshots in snapshot mode.
- Fleet policy interval (default 1 h), the daily webhook batch, asleep-host behaviour, and the overnight-idle test on a real seat: **docs only, open**. The local proxy shows the predicate, not Fleet.

### Goal 11: org kill switch

Optional and absent on OSS. If `kill.json` and `org.pub` are in the managed directory (`/Library/Application Support/Fairlead` or `/etc/fairlead`; `FAIRLEAD_MANAGED_DIR` overrides in debug builds only, a release build ignores it because an env var the seat user controls would otherwise let them point the trust root at their own `org.pub` and self-signed clear), the next hooked call reads them before Cedar. An Ed25519-valid `deny-all` makes every hooked call Deny (exit 2, signed receipt when armed) and writes `killed.stamp` next to `last-armed.json`. After that the seat stays denied until a signed `clear` that names the stamped id, even if `kill.json` is deleted. A laptop that was never killed (no stamp, no blob) is unchanged. There is no TTL: expiry into allow is fail-open, expiry into deny bricks a seat the org did not kill. A local admin who deletes the stamp and the blob gets fail-open on the next call; the pin query is the signal. A process that already skipped the hooks is not stopped. Operational limits: `kill.json` and `org.pub` must be readable by the seat user (an unreadable file is ignored with a stderr line, so a never-killed seat is not bricked, but a mis-moded push also does not kill); a symlink, FIFO, or file over 64 KiB in place of either is ignored, and in place of the stamp it counts as killed until any signed clear; every `id` must be unique per incident, because a `clear` for a reused id can lift a later kill; the stamp is written by the hook, so on a root-owned pack it cannot be created and stickiness then depends on MDM keeping `kill.json` in place until the org signs a clear.
