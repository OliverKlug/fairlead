# Enterprise bundle (Goal 11, F-BYP-06/07/08)

Files only. Fairlead does not implement MDM, a heartbeat daemon, or a dashboard. The customer's
MDM drops these files and the customer's osquery / Fleet / Kolide runs the query. If they never
load the query, the pin is a silent hole and Fairlead still works.

| File | What it is |
|---|---|
| `fleet-pin-policy.sql` | Fleet policy. Pass if no IDE agent is running, or the managed hooks file and the binary still hash to the armed values. |
| `check-pin-policy.sh` | Proves that predicate with sqlite3 (no osquery needed). Run it after editing the SQL. |
| `fairlead-hook` | Space-free wrapper script. Exports `FAIRLEAD_ROOT` and `FAIRLEAD_HOOKS`, then execs the binary. Cursor 3.6.21 on macOS runs `command` through a shell (observed once, 2026-10-08), but Cursor documents no shell and other versions or OSes are unverified, so the environment lives in the wrapper instead of an env prefix in `command`. Edit the three paths, install root-owned 755. |
| `check-install.sh` | Builds a temp install, runs the hook the way Cursor execs it, compares receipt hashes to the pin, optionally runs the query on real osquery (`OSQUERYD=...`). |
| `check-idle-proxy.py` | The same predicate under a real osquery snapshot schedule while the pinned files change. Not Fleet. |
| `live-probe-cursor.sh` | Human-run live Cursor probe (precedence, exec semantics, reload, wrapper). Restores your hooks files on `teardown`. |
| `claude-managed-settings.json` | Claude Code managed settings: our four hooks with `onFailure: block`, `allowManagedHooksOnly`, strict sandbox. |
| `claude-managed-strict.json` | Opt-in drop-in (`managed-settings.d/50-strict.json`): `dontAsk` plus an allowlist, managed-only permission rules, no bypass or auto mode. Not written by `install-hooks`. Costs: it breaks Auto-run, the allowlist duplicates Cedar, read-only Bash and working-directory reads still run, `sh -c` evades Bash text rules, and `--permission-mode acceptEdits` is not locked. `doctor` only notes whether it is applied. |

## Managed paths (the customer's MDM places them; Cursor does not)

- Cursor hooks: macOS `/Library/Application Support/Cursor/hooks.json`, Linux `/etc/cursor/hooks.json`, Windows `C:\ProgramData\Cursor\hooks.json`. Priority Enterprise, Team, Project, User, but every matching hook from every source runs and Cursor merges the answers: any `deny` beats `ask` beats `allow`, regardless of source (Cursor Hooks docs). Priority only decides non-permission fields such as `followup_message`. So a user hook cannot override a managed deny, but nothing stops a user hook from adding its own. Docs-sourced; see the Cursor probe status below. A missing managed file is fail-open (lower sources still run); Cursor has no "hooks required" key.
- Claude Code: macOS `/Library/Application Support/ClaudeCode/managed-settings.json`, Linux `/etc/claude-code/managed-settings.json`, plus `managed-settings.d/*.json` beside it (`doctor` reads all of them; `FAIRLEAD_CLAUDE_MANAGED_DIR` overrides the directory in debug builds only). Needs Claude Code 2.1.139 or newer: older binaries silently ignore `args` and would run the binary with no arguments (fail-open). Needs 2.1.295 or newer for `onFailure: block`: older binaries ignore the key (probed on 2.1.285), so a failing hook still lets the call through, and `doctor` warns (plain seat) or refuses (managed seat) on an older `claude --version`. `allowManagedHooksOnly` only picks which settings files may load hooks and is managed-only (`--settings` cannot set it). Docs-sourced, untested live: switching it on also disables the seat user's own hooks, so it is not safe to probe on a working machine. It does not hash the hook binary, and with `onFailure: block` (2.1.295+) a deleted binary or a crash blocks; on older versions a deleted binary (exit 127) lets the action proceed. The osquery binary hash is the finding.
- Org kill switch (optional): `kill.json` and `org.pub` in `/Library/Application Support/Fairlead` (macOS) or `/etc/fairlead`. Absent means OSS behaviour.

## Order that makes the Goal 9 pin true

1. Install the binary and the pack (`policies/`, `tests/doctor/cases.json`) at their final paths, e.g. `/usr/local/lib/fairlead/fairlead` and `/usr/local/share/fairlead`.
2. Stage the hooks from that installed binary, so the embedded command is the installed path: `FAIRLEAD_ROOT=/usr/local/share/fairlead /usr/local/lib/fairlead/fairlead install-hooks /tmp/stage`, then take `/tmp/stage/.cursor/hooks.json`. `install-hooks` embeds the canonicalized (symlink-resolved) path of the binary, not the path you typed, so run it from the real path.
3. The hook process needs the pack path and the hooks path. Called directly, it only finds a pack through the compile-time `pack/` directory, which is wrong for any installed binary and denies every call. Prefer the wrapper over an env prefix in `command`: an env prefix worked on Cursor 3.6.21 / macOS (it runs through a shell), but that is undocumented and unverified elsewhere, and the wrapper keeps `hooks.json` free of paths so one file is the pinned object. Install `fairlead-hook` (paths edited) at `/usr/local/lib/fairlead/fairlead-hook`, then rewrite each staged `command` from `FAIRLEAD_HOOKS=<staging path> <binary> hook cursor shell` to `<wrapper> cursor shell` (the wrapper exports the managed `FAIRLEAD_HOOKS`; leave the staging-path prefix in and the pinned file names a path that does not exist on the seat), for example `sed 's|FAIRLEAD_HOOKS=[^ ]* /usr/local/lib/fairlead/fairlead hook |/usr/local/lib/fairlead/fairlead-hook |'` (a staging path with a space is double-quoted, so adjust the pattern). Then `! grep 'fairlead hook ' <file>` must hold: a sed that matches nothing exits 0, and the hash of a file that still calls the binary directly matches its own pin, so Fleet stays green while Cursor runs the binary with no `FAIRLEAD_ROOT`. `FAIRLEAD_HOOKS` is what makes receipts carry the real `hooks_sha256` instead of the absent-hooks constant. `./check-install.sh` proves the wrapper reaches the hook (without it the receipt carries the wrong pack and the absent-hooks hash).
4. MDM places that file at the managed path (root-owned, mode 644).
5. On a reference machine run `FAIRLEAD_ROOT=... FAIRLEAD_HOOKS='<managed hooks path>' fairlead arm`. Leaving `FAIRLEAD_HOOKS` unset pins the absent-hooks constant, which is a pin of the wrong object and fails a healthy seat in osquery; with it set to a missing path, `doctor` refuses but still prints a hash first, so do not copy hashes from a failed run. `hooks_sha256` covers only the file `FAIRLEAD_HOOKS` names; the Claude settings file is not in the pin. The stock `fleet-pin-policy.sql` does not pin the Claude file: add its own EXISTS hash row before shipping `claude-managed-settings.json`, or editing its `command` leaves the pins in this query green.
6. `fairlead doctor` prints `binary_sha256` and `hooks_sha256`. Put those, the paths, the wrapper's `sha256`, and (if used) the Claude file's `sha256` into the `@...@` slots, together with `shasum -a 256` of `policies/baseline.cedar` and `policies/coding-agent.cedarschema` (`@CEDAR_*@`, `@SCHEMA_*@`); the wrapper is pinned too, because editing it bypasses the pin. An armed seat's hook now refuses before Cedar when the pack bytes, the binary, or the file `FAIRLEAD_HOOKS` names differ from `last-armed.json` (`fairlead deny: policy drift`, `binary drift`, `hooks drift`), and, when `org.pub` is installed, when `pack.json` does not carry that key's signature over the pack digest (`fairlead deny: pack signature`). On a managed seat (`org.pub`, `armed.stamp`, or a pin in the managed directory) the pin is read only from the managed directory, which must be root-owned with a root-owned 0644 `last-armed.json`: a writable pin or directory denies (`pin writable`), and a missing pin denies once `armed.stamp` exists (`pin missing`). Run `arm` as root (it writes `armed.stamp`, then the pin); run as a non-root user it prints both bodies and writes nothing. A self-managed seat is the same layout without `org.pub` and without `pack.json`: no signed successor, so an update is `sudo fairlead arm --i-reviewed-pack`, and the pack signature check does not apply. With no managed directory the pin stays in the docs root and a same-UID rewrite of pack and pin together still matches. Host sandbox: `claude-managed-settings.json` also sets `sandbox.enabled`, `allowUnsandboxedCommands: false` and `failIfUnavailable: true`, and on a managed seat `doctor` and `arm` refuse when the effective Claude settings (all readable scopes, first-wins) lack them, drop or loosen the Fairlead hooks, set `disableAllHooks`, or a Cursor `sandbox.json` sets `insecure_none`. Fairlead checks that config; the host enforces it. Migrating: a managed directory that exists but is user-owned used to be accepted by `arm`; now `arm` and `doctor` print the `chown root ... && chmod go-w ...` fix, or remove the directory to stay on the docs pin. The pin alone does not bind the agent: copy hooks to the Cursor managed path and install a root-owned binary as above, or a user-owned `command` points away from the checker. A legitimate update on an org seat can ship signed: `pack.json` with `generation` (pin + 1), `binary_sha256` and optional `not_after` (unix seconds) is accepted in place of the pinned pack and binary while the old pin keeps working; `arm` then installs the new pin. Without a signed successor an update denies every call until `arm` runs again. What no file mode closes: a local admin, a user-owned binary or hooks path (on a managed seat `doctor` and `arm` refuse until the managed dir, the binary and the `FAIRLEAD_HOOKS` file are root-owned with no group/other write bit, file and parent; mode bits only, no ACLs), and anything that never reaches a hook. The detector for those is osquery's `sha256` of the binary and of those two pack files against `@CEDAR_SHA256@` and `@SCHEMA_SHA256@`. Do not paste the receipt's `policy_pack_sha256` into those slots: that digest is `sha256` of a domain prefix plus the two file digests, and osquery will never write it in the `hash` table. The three-file query (hooks, binary, wrapper) does not see a cedar edit at all. Every pinned file must stay under osquery's `read_max` (50MB default): above it the hash columns come back empty and the policy fails on a healthy seat. The release binary is about 10MB; a debug build (about 31MB) is fine for tests only.

Claude's `env` block is how `FAIRLEAD_ROOT` reaches the exec-form hook. The docs say settings `env` reaches hook subprocesses; Closed live on Claude Code 2.1.285 (2026-10-08): the real binary was spawned in exec form by a project `claude -p` session and read `FAIRLEAD_ROOT` from the settings `env` over a conflicting shell export. `PreToolUse` through the real binary was then observed on 2.1.285 with a local mock Anthropic server (allow and exit-2 block, also under `--dangerously-skip-permissions`; see `RESIDUAL-RISK.md`). The sample sets `FAIRLEAD_HOOKS` too, so Claude receipts carry the same `hooks_sha256` the pin query checks. Not run: the managed path with `allowManagedHooksOnly` (needs admin, switches off the seat user's own hooks).

## Org kill switch files

`org.pub`: 64 lowercase hex chars, the org's Ed25519 public key. `kill.json`: a flat JSON body plus `"sig"`, the Ed25519 signature (hex) over the body without `sig`, canonicalized per RFC 8785 (for these flat bodies: compact JSON, keys sorted). Fairlead ships no signer; the org key lives outside this repo.

```json
{"v":1,"decision":"deny-all","id":"incident-2026-10-06"}
{"v":1,"decision":"clear","id":"clear-2026-10-07","clears":"incident-2026-10-06"}
```

`id` is 1 to 64 chars of `[A-Za-z0-9._-]`. A valid `deny-all` denies every hooked call and writes `killed.stamp` beside `last-armed.json`. The seat then stays denied until a valid `clear` naming that id, even if `kill.json` is deleted. A garbage or wrong-key blob on a seat that was never killed is ignored. There is no TTL.

## Falsifiers (run these before claiming it works)

- `./check-pin-policy.sh`: sqlite3 model of the predicate, 17 cases (quit IDE passes, a lingering `Cursor Helper` passes, open IDE passes, `hooks.json`, binary, wrapper, `baseline.cedar`, or the schema edited or deleted fails, Windows and versioned-path Claude arms fail when a pin is bad). One case is a labelled known gap: an npm-fallback Claude runs as `node` and is not matched.
- `OSQUERYD=/path/to/osqueryd ./check-install.sh`: real osquery on a real temp install. Closed in this repo's last run; needs a built `target/debug/fairlead` and a running Cursor/claude process for the IDE-running cases (it skips them otherwise).
- `OSQUERYD=/path/to/osqueryd python3 check-idle-proxy.py`: the same predicate under a real 2 s osquery snapshot schedule while the pinned files are edited, deleted and restored (takes about a minute; needs a running Cursor or claude). This is not Fleet: no policy interval, no webhooks, no asleep-host state.
- `./live-probe-cursor.sh setup a|b`, `read`, `teardown`: the human-run Cursor probe (managed vs user precedence, shell vs argv exec, hot reload, wrapper exec from the managed path). Needs sudo and a second Cursor window; restores your own `~/.cursor/hooks.json` byte for byte on `teardown`. Run once on Cursor 3.6.21, macOS 15.7.3, Pro plan (2026-10-08): all four questions confirmed.
- On a reference seat with the query loaded: leave the IDE quit overnight, must not page. Delete the managed `hooks.json` with Cursor running, must fail within one policy interval (Fleet default is one hour).
- Managed hooks deny, a user `~/.cursor/hooks.json` allows: the command must still be blocked. Cursor's docs say any deny from any source wins; Observed live on Cursor 3.6.21 / Pro (2026-10-08): both sources ran and a managed deny beat a user allow. The opposite direction (user deny, managed allow) was observed too: deny wins from either source. If a version stops loading the managed file, it is not the gate.
- Kill: `cargo test -p fairlead-core kill` (state machine, plus a real hook process: deny, `kill.json` deleted still denies, signed clear allows).
- Delete the stamp and the blob together: the next call allows. That is the named residual; the pin query is the signal, not Fairlead.

## Status (2026-10-08)

Proven live: Claude exec form plus settings `env` on 2.1.285; real `PreToolUse` allow and exit-2 block under `claude -p` and `--dangerously-skip-permissions` on 2.1.285 against a mock API (not a real model); pin predicate on real osquery and a real snapshot scheduler; temp-install hook exec with receipt hashes equal to the pin. Observed live on Cursor 3.6.21 / macOS 15.7.3 / Pro (one machine, one version): the managed file loaded on a Pro seat, both sources run and the managed deny wins, `command` runs through a shell and a quoted path with a space works, the managed file hot-reloads without a restart (restart absence is the operator's statement), and the real wrapper at the managed path denied a command with a signed receipt whose `hooks_sha256` equals sha256 of the managed file. Docs-only: `allowManagedHooksOnly`, Claude `PermissionRequest` through the real binary and YOLO subagents, Fleet's 1 h policy interval, daily webhook batch and asleep-host behaviour. Open until a customer seat runs them: Cursor Teams/Enterprise and other Cursor versions or OSes, and the overnight idle and delete-under-load tests on a Fleet seat. Known gap: an npm-fallback Claude Code runs as `node` and is not matched by the process predicate. Kill switch: `FAIRLEAD_MANAGED_DIR` is honored by debug builds only, `fairlead-hook` unsets it, and ids in `kill.json` must never be reused.
